# Тема 4 - система регистрации обращений пользователей

## Цели внедрения

Ускорить регистрацию и обработку обращений

Обеспечить единый учёт и историю всех обращений

Устранить возможность потери заявок

Сформировывать отчёты по обращениям

## План внедрения

| Этап | Содержание работ | Результат | Срок | Отвественность |
| ---- | ---------------- | --------- | ---- | -------------- |
| Анализ | Сбор требований, анализ существующего процесса обработки обработки | Требования и план работ | 2 дня | Руководитель проекта |
| Подготовка | Подготовка серверов и баз данных | Готовая среда для внедрения | 2 дня | Системный администратор |
| Настройка | Установка системы, натсрокйка ролей, прав доступа, категорий обращений и уведомлений | Натсроенная система | 4 дня | Системный администратор |
| Тестирование | Проверка функций регистрации назначения и отслеживания заявок | Отчёт о тестировании и исправления | 2 дня | Бета-Тестеры |
| Обучение | Обучение сотрудников и заявителей к работе системы | Обученные пользователи | 2 дня | Тех-Поддержка |
| Запуск | Переход в полнное использование и поддержка на начальном этапе | Система в работе, стабильная работа | 2дня | Руководитель проекта |

**Итого: 14 рабочих дней**

## Отвественные за проект

Руководитель проека - управление самим проектом

Разработчики - сами создают софт и поддерживают его

Бета-Тестеры - тестируют функции на этапе разработки

Системный администратор - установка настройка и интеграция

Тех Поддержка - обучение пользователей и сбор обратной связи 

## Что нужно для реализации проекта

Сервер для установки системы

Места для сотрудников тех поддержки

Иструкции и справки для пользователей

## Риски и меры контроля

| Риск | Решение |
| ---- | ------- |
| Сопративление новой системе | Провести обучение и показать уникальные способности которых нету у прошлой системы |
| Ошибки при настройке прав доступа | Провести тесты и сделать нужные багфиксы |
| Потеря данных при переносе сарых обращений | Создание резервной коппи перед переносом данных |
| Срыв сроков из за загруженности разработчиков | Резерв времени на разработку |

## Успешное завершение проекта достигаеться только если:

Все обращения делаються в системе и не теряються

Пользователи и сотрудники обученны и пользуються системой

Система работает стабильно и без ошибок в первые дни использования
